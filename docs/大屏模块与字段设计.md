# QuickAudience 商家分层运营大屏 · 模块与字段设计

**使用对象**：商家运营负责人
**数据源**：`data/QuickAudience商家分层练习-处理方式(1).xlsx` → `商家明细` sheet（2000 家，47 字段）

---

## 0. 一个必须先说明的数据前提

原始表只有 **近 12 个月的汇总消耗**（三通道各一列），**没有月度明细**，因此无法直接支持"筛选时间段"。

处理方式：ETL 层把每家商家每个通道的年度总额，**确定性地展开成 12 个月**（2025-09 ~ 2026-08），展开规则不是随机数，而是由表内已有字段驱动：

| 展开因子 | 来源字段 | 规则 |
|---|---|---|
| 趋势形态 | `近3月消耗环比趋势` | 上升→尾部 3 月上翘；持平→平；下降→尾部下滑；连续下降→尾部连续下滑 |
| 大促脉冲 | `近12月大促参与次数` | 1 月（年货节）/ 6 月（618）/ 11 月（双11）加权，权重随大促次数放大 |
| 起投月 | `签约时间` | 签约前的月份消耗恒为 0，再在可用月份上归一化 |
| 微扰动 | `商家ID` 哈希 | 固定种子，同一商家每次跑结果一致 |

**任意时间窗口的三通道消耗之和 = 原表年度总额**（窗口取满 12 月时严格相等）。所有时间筛选、环比、预警都建立在这张月度事实表上。

同理，原表没有**销售负责人**字段，按「所在区域 + 商家ID 哈希」确定性分配到 14 名虚拟销售，用于飞书通知的收件人路由。

## 1. 全局筛选栏（作用于全部 6 个模块）

| 控件 | 取数字段 | 说明 |
|---|---|---|
| 时间段 | 月度事实表 `month` | 预设近 1/3/6/12 月 + 自定义起止月 |
| 行业 | `所属行业` | 8 类，多选 |
| 区域 | `所在区域` | 7 大区，多选 |
| 客户来源 | `客户来源` | 直客 / 渠道代理 |
| 合同类型 | `合同类型` | 订阅+消耗 / 纯消耗 |
| 分层 | `分层结果` | SKA / KA / 腰部 / 基础长尾 / 新客观察期 / 未激活 |
| 战略客户 | `是否战略客户` | 是 / 否 |

**分层口径开关**：`区间分层`（按所选时间窗重算档位分与综合分）/ `年度基准分层`（直接用表内 AS 列）。默认区间分层——否则时间筛选对分层无影响。

## 2. 模块清单

### M1 总览看板（回答"这段时间盘子怎么样"）

**KPI 行（8 个统计卡）**

| 指标 | 计算口径 |
|---|---|
| 商家总数 | 筛选后 `商家ID` 去重计数 |
| 活跃商家数 | 区间内消耗 > 0 的商家数 |
| 消耗总金额 | Σ 区间三通道消耗（**hero 数字**，含环比 delta + 12 点迷你走势） |
| 户均消耗 ARPU | 消耗总额 ÷ 活跃商家数 |
| 未激活商家数 | 区间内消耗 = 0 且 `合作月数` ≥ 3 |
| 预警商家数 | 命中任一预警规则（见 M5） |
| SKA+KA 消耗占比 | 头部两层消耗 ÷ 总消耗（金字塔健康度，应 > 60%） |
| 平均触达场景数 | `触达场景数(个)` 均值（层间差距的核心解释变量） |

**图表**

| 图 | 形态 | 取数字段 |
|---|---|---|
| 消耗趋势 | 堆叠面积 + 折线（3 系列：短信/AI外呼/Push企微） | 月度事实表 × `channel` |
| 分层金字塔 | 横向条形（左家数、右消耗占比双列） | `分层结果` × 家数/消耗 |
| 消耗集中度 | 洛伦兹曲线（累计商家占比 × 累计消耗占比） | `累计消耗金额%` 思路，按窗口重算 |
| 行业消耗 TOP8 | 横向条形（单一色 + 直接标值） | `所属行业` |
| 区域消耗分布 | 横向条形 | `所在区域` |

### M2 BY 客户分层（回答"客户结构长什么样、谁该升谁该降"）

| 图 | 形态 | 取数字段 |
|---|---|---|
| 分层家数 vs 消耗贡献 | 百分比堆叠条形（两条：家数结构 / 消耗结构，直接标名） | `分层结果` |
| 价值-潜力四象限 | 气泡散点（X=潜力分 0-30，Y=价值分 0-40，气泡=区间消耗） | `潜力分`/`价值分`/消耗 |
| 分层 × 行业 | 热力图（单一蓝色顺序色阶） | `分层结果` × `所属行业` |
| 生命周期漏斗 | 漏斗 | `生命周期阶段` |
| 层级迁徙 | 表格：本期分层 vs 年度基准分层，标出升/降级候选 | 区间综合分 vs `综合分` |
| 四维雷达 | 雷达图，各层平均 价值/活跃/潜力/健康 分 | `价值分`/`活跃分`/`潜力分`/`健康分` |

四象限里两类样本单独打标（icon + 文字标签，不靠颜色单独承载）：
- **高潜新签**：`合作月数` < 6 且消耗低于中位、潜力分 ≥ 24
- **衰退 KA**：分层 ∈ {SKA, KA} 且 `近3月消耗环比趋势` = 连续下降

### M3 BY 产品/通道消耗（回答"哪条通道在涨、还能往哪推"）

| 图 | 形态 | 取数字段 |
|---|---|---|
| 三通道月度趋势 | 多折线（3 系列，端点直接标值） | 月度事实表 × `channel` |
| 通道消耗结构 | 环形（3 段）+ 中心总额 | 三通道合计 |
| 分层 × 通道结构 | 百分比堆叠条形（每层一行） | `分层结果` × `channel` |
| 通道渗透率 | 分组条形：各层「使用该通道的商家占比」 | 区间内该通道消耗 > 0 |
| 场景数渗透 | 横向条形：各层平均 `触达场景数` + 接入深度 | `触达场景数(个)`、`数据接入深度` |
| 通道 ARPU / 环比 | 3 个统计卡（值 + 环比 delta + 迷你走势） | 通道消耗 ÷ 使用商家数 |

### M4 商家明细 + 运营动作（回答"具体这家怎么办"）

表格列（支持排序、搜索、导出、逐行推送飞书）：

`商家ID` · `商家名称` · `所属行业` · `所在区域` · `分层结果` · `综合分` ·
`价值/活跃/潜力/健康` 四维分 · 区间消耗合计 · 短信/AI外呼/Push企微 三列 ·
`触达场景数` · `数据接入深度` · `近3月消耗环比趋势` · **预警标签** ·
**可拓展预算空间**（= `年度营销预算`×1万 − 区间消耗，销售的报价天花板） ·
**推荐运营动作**（由 `主打通道策略` + 命中预警规则合成） · **负责销售**

### M5 预警看板（回答"哪些客户在掉，掉多快"）

7 条规则，输出等级（高危/中危/关注）：

| 规则 | 判定 | 等级 |
|---|---|---|
| 连续下降 | `近3月消耗环比趋势` = 连续下降 | 高危 |
| 消耗断崖 | 最近 1 月环比跌幅 > 50% 且绝对额 > 1 万 | 高危 |
| 头部流失预警 | 分层 ∈ {SKA,KA} 且 `生命周期阶段` = 流失预警 | 高危 |
| 活跃衰减 | `月均活跃发送天数` < 5 且区间有消耗 | 中危 |
| 场景收缩 | `触达场景数` ≤ 1 且分层 ∈ {SKA,KA,腰部} | 中危 |
| 预算未消化 | 可拓展预算空间 / 年度预算 > 80% 且预算 > 100 万 | 关注 |
| 沉默超期 | 区间消耗 = 0 且 `合作月数` ≥ 3 | 关注 |

**图表**：预警等级分布（状态色 + icon）· 预警规则命中 TOP · 预警商家消耗趋势（红线）· 预警清单表（含金额风险敞口 Σ 预警商家消耗）

### M6 动作提醒 & 飞书通知（回答"谁去跟，跟了没有"）

- **待办动作卡片流**：由「分层策略 × 命中预警」生成，含 动作标题 / 商家 / 层级 / 风险金额 / 建议动作 / 负责销售 / 截止日 / 状态
- **飞书推送**：单条推送 + 批量推送，生成飞书消息卡片（interactive card）JSON；配置 Webhook 后直发群机器人，未配置则进入 Dry-run 预览
- **推送记录**：时间 / 商家 / 收件销售 / 规则 / 状态

## 3. 视觉与图表规范（dataviz 校验通过）

- **深色大屏**：页面底 `#0d1016`，卡片面 `#141821`
- **通道 3 色**（categorical，all-pairs 全通过）：短信 `#3987e5` · AI外呼 `#d95926` · Push及企微 `#199e70`
- **分层 6 类**：SKA→基础长尾 使用单蓝顺序色阶 `#86b6ef→#3987e5→#256abf→#184f95`（ordinal 校验通过，层级本身有序），新客观察期 `#d55181`、未激活 `#898781` 两个非序类单列；该配色只用在**已直接标注层级名**的图形上（条形/堆叠/表格色块），绝不在散点上单独承载识别。
- **预警状态色**（保留色，永远 icon + 文字同时出现）：高危 `#d03b3b` · 中危 `#ec835a` · 关注 `#fab219` · 正常 `#0ca30c`
- 无双 Y 轴；柱条 ≤ 24px、4px 圆角数据端；折线 2px；网格线为实线发丝线；每图配 tooltip，值不只靠 tooltip 可得。
